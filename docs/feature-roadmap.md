# Scanline 特性列表与里程碑提案

> 依据:[competitive-landscape.md](research/competitive-landscape.md)(2026-11-08 调研)。
> 编号约定:P# = 调研文档痛点编号,G# = 机会缺口编号。
> 架构前提:nsh 应用外壳 + nsh Terminal 元素(平台原生文字引擎)+ ScanlineCore(自研 `TerminalEmulator`,v0.2 起)+ portable-pty(ConPTY)+ 可插拔本地优先 AI。

---

## 一、定位一句话(经调研校准)

**全六平台原生(非 Electron)的 MIT 开源终端,自带 BYOK/本地优先的 AI 与本地审批执行范式,CRT 美学作为第一设计语言,免订阅。**

调研校准说明:缺口 G1 的原始表述是「GPU 原生渲染 + 全平台 + MIT + 内置 AI + 免订阅」;采用 nsh 后我们的渲染是「平台原生文字引擎」而非自研 GPU shader——但组合缺口依然成立且更宽:**六平台覆盖(Termius 有移动端但闭源订阅;Tabby 有 Web 但 Electron)+ MIT + BYOK AI + 免订阅,零竞品同时具备**(G1、G9、G10 交叉)。

### 明确不做(现阶段)

- 自家云服务/账号体系/遥测(P10、P12 是反面教材:Warp/Termius 的流失源头)
- 团队协作/Drive 类功能(市场已被 Warp 占,且与我们定位冲突)
- WezTerm 式自研 mux(tmux/ssh 已覆盖;持会话走 Mosh 评估)
- 自研 GPU 渲染引擎(仅当 nsh 原生引擎性能验证失败时才重新评估——M0 基准测试是裁决点)

## 三、里程碑(2026-11-08 调整:公开 MVP 门槛 = P2 完成)

> 调整说明:发布策略从「尽早公开发布」改为「打磨私藏、带差异化亮相」——公开发布的门槛上移到 P2 核心完成。
> **构建顺序不变**(P0 → P1 → P2,地基逻辑不可跳过),变的只是「什么时候对外宣布」。
> 风险对冲:为避免「发布太晚、反馈太迟」,Alpha A 起即建 3–5 人 dogfood 圈,反馈闭环照常运转。

### M0 — 技术验证尖刺(现在,1–2 周当量,**仅 Windows**)
**目的:在写正式代码前,用一次性 spike 裁决风险。全程只在 Windows 上做。**
- [ ] nsh Windows hello app 跑通(`nsh run --target windows`)
- [ ] Terminal 元素 + ConPTY 接线 spike:重输出场景(cat 大文件/yes/htop)测延迟与吞吐
- [ ] 自定义 ANSI 配色能力验证(CRT 主题的前提)
- [ ] 连字能力验证(DirectWrite 表现)
- [ ] 鼠标上报缺口:向上游提 issue 并评估 PR 可行性
- [ ] (仅可行性验证,非移植,约半天)nsh Android 样例 APK 能否出包、Terminal 元素能否连 SSH 会话——Android 已进发布门槛,此风险必须尽早确认;若失败立即上报重议发布门槛,不展开任何 Android 开发

### M1 = Alpha A「First light」(内部,**仅 Windows**)
P0 九项(打包仅 Windows)。不公开发布;自用 + dogfood 圈。出口标准:Windows 上开发者愿意拿它当日常 shell 窗口,延迟预算达标。

### M2 = Alpha B「Daily driver」(内部,**仅 Windows**)
特性 10–12 + 19(标签/分屏、回滚搜索、ScanlineCore、命令块 UI、CRT 主题族)。出口标准:自家模拟器驱动全部界面,命令块数据模型落地。

### M3 = Alpha C「AI surfaces」(内部,**仅 Windows**)
特性 13–17(解释输出、幽灵补全、Ctrl+K、BYOK 三端点)。出口标准:纯本地模型路径零云依赖可用。

### M4 = Beta「Differentiated」(P2 核心 + 平台铺开)
**进入条件:Windows 侧 M1–M3 全部出口标准达成。**
- 第一步(特性):信任基础设施、agent 分屏、扫描线滤镜(20–22),信任基础设施最优先
- 第二步(平台铺开,顺序执行,每平台以「功能对齐 + 性能预算达标」为移植完成标准):
  1. **macOS + Linux** 移植(nsh 同一代码库,重点回归 GTK/AppKit 集成差异)
  2. **Web** 目标(`nsh run --target web`)
  3. **Android** 目标(APK 分发;移动端以 SSH/WS 连回开发机为主)
- iOS 不在发布门槛,发布后跟进

### **MVP = M4 完成 = 公开发布时刻**
**发布门槛:桌面三平台 + Web + Android。** 品牌 + 差异化一起亮相(HN/Product Hunt 首发)。

### 发布后 → v1.0(强制清单,非可选)
iOS、图片协议四项全支持、kitty keyboard protocol、SSH 主机库(含端口映射/隧道管理、SFTP 文件传输——Xshell 式)、**远程桌面会话类型(IronRDP)**、会话插件机制阶段二(进程外 provider)、性能 HUD、自托管同步。

### v1.0「Stability = 完整版」
**最终版本必须完整:28 项特性无一豁免**(2026-11-08 拍板)。上述强制清单全部落地 + 协议/配置/AI 插件稳定性承诺、全平台包管理器分发、文档站、发布节奏承诺(G7:活跃维护本身是卖点)。

## 四、MVP 圈定(2026-11-08 新定义)

**公开 MVP = P0 + P1 + P2 核心集全部落地:三桌面 + Web + Android 的原生终端,命令块 AI + 执行信任基础设施(差异预览/本地审批/回放)、agent 分屏、CRT 主题族与扫描线滤镜,MIT 开源,免订阅。**
(Android 首要进门槛:APK 直接分发;iOS 因商店审核门槛,发布后跟进。)
**最终版本(v1.0)必须完整:P2 全部 28 项无一豁免**——发布后强制清单:iOS、图片协议全支持、kitty keyboard protocol、SSH vault、自托管同步、性能 HUD。

## 五、决策记录

1. **移动端与发布门槛**(2026-11-08 拍板):**Android 首要支持、进发布门槛**——APK 直接分发无商店审核,发布门槛最低;iOS 因 App Store 审核/开发者账号费用,发布后跟进。
2. **完整性承诺**(2026-11-08 拍板,2026-11-09 扩充):**最终版本(v1.0)必须完整**,P2 特性无一豁免(现 30 项)。图片协议/键盘协议/SSH vault(含文件/隧道/会话类型)/同步/HUD 为「发布后 → v1.0 强制清单」,不是可选 fast-follow,不允许无限期拖延。远程桌面建议排 v1.0 后第一波(1.x)——产品级工程量,待定。
3. **平台策略**(2026-11-09 拍板):**Windows 为唯一开发与验收平台**——开发、测试、打磨全部在 Windows 完成,达到出口标准后才逐一兼容其他平台(顺序:macOS/Linux → Web → Android;iOS 发布后跟进)。不做多平台并行开发;每进入一个新平台,以「功能对齐 + 性能预算达标」为移植完成标准。
4. **RDP 与会话插件**(2026-11-09 拍板):远程桌面进 v1.0 强制清单(路线 = IronRDP);UU 远程作为后续扩展——会话插件机制(阶段二)就绪后,以 provider 插件形式接入;会话类型从 MVP 起走 SessionType trait 注册表,为插件化预留接缝。
5. **全产品插件化**(2026-11-09 拍板):Scanline = 微内核 + 插件组成(见特性 29)——AI 层、主题、视图、会话类型全部插件化;热路径(VT 解析/网格/块存储)留内核;外部插件走 nsh 签名包 + 进程外 provider,许可证隔离;「AI-optional」成为可能(整组 AI 插件可关闭)。

> 已作废的旧决策点:标签/CRT 主题「进不进 MVP」——P2 全量视角下自然在列,无需再议。
